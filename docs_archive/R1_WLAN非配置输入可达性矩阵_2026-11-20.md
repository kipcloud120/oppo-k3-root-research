## 0. 结论先行

1. **R1 交付：一张非配置输入可达性矩阵（§2）+ 候选排序（§3）+ 明确未覆盖范围（§4）+ 候选 A 离线审计（§6）。本阶段不下漏洞结论。**
2. **三个输入面类别在模块二进制中被证实存在且"输入可控"**：① net_device ioctl（`hdd_ioctl`，两个命令号）；② cfg80211 testmode / FTM（`wlan_ioctl_ftm_testmode_cmd`）；③ cfg80211 vendor/管理帧注册面（大量 `wlan_hdd_cfg80211_*`）。它们均有用户态可控字节 + 明确的拷贝链。
3. **可达域是决定性约束，但不能只建"shell 直接访问"模型**：驱动侧 ioctl / cfg80211 面要求持 wlan0 或 `CAP_NET_ADMIN`——`oplus_wifi_service`（uid 0，net_admin 组）满足，shell（uid 2000）不满足。**但项目已证实一条 shell → Binder tx 10070 → 受限 UID 0（`u:r:oplus_wifi_service:s0`，含 NET_ADMIN/NET_RAW/SYS_MODULE）命令执行的间接路径（§23 + P1 原始日志）**；该子进程域正是驱动面 A/B 的可达域。因此可达性必须**分两栏**记录：shell 直接访问（否）+ 受限 UID 0 代理访问（域满足，是否真能驱动 ioctl 未证）。
4. **候选排序结论（修正）**：**首选 = 候选 A「ioctl `0x89f1` → `hdd_driver_command`」**——§6 离线审计确认它是有界命令分发器（长度上界 `0x2000`、显式 NUL 终止、98 项命令白名单 `strncasecmp`、未匹配 `ENOTSUPP`、全路径释放），且在 UID 0 代理域可达。**次选 = 候选 B「FTM testmode」**（`≤0x800` + `__check_object_size`）。**必须诚实标注**：现有物料**不能静态证明** `/odm/bin/iwpriv` 或 `executeDriverCommand` 最终落到 `0x89f1`——这是用户态命令链与内核态 ioctl 两条独立路径，连接点未证。本轮不宣告"无 R3 候选"，但也**不在当前设备做动态输入**；停在授权门前。

### 2.1 关于 shell 可达的"Binder 私有事务"通道（非 .ko 面，但必须并入判断）—— **v12.3.1 更正**

> **本小节初版错误已撤回**：初版仅引用 `F16_WIFI_FTM_TRACE.md` §12（早期对"分号/管道注入"失败的撤回），写成"所有注入均被拒绝、不产生 uid 0"。该表述忽略了此后更晚的正向实测，属事实错误。以下为按原始证据更正后的结论。

**按时间顺序完整重建这条链的证据**：

| 阶段 | 文档 / 证据 | 结论 |
|---|---|---|
| ① 早期失败（分号/管道/重定向） | `F16_WIFI_FTM_TRACE.md` §12 | `;`/`|`/`>` 命 regex 黑名单 → `-3 INVAILD_PARAMETER`；"实锤"撤回。**该撤回只针对这些字符** |
| ② 黑名单逐字节分析 | `WIFI_P1_ROOT_COMMAND_AUDIT.md` §3 | regex 仅覆盖 11 字符 `@#$%&*^:;?|`，**`\n`(0x0A) 与反引号(0x60) 不在其中**；`\n` 是 sh 命令分隔符、反引号是命令替换 ⇒ 可穿越 |
| ③ **正向实测（决定性）** | `P1_L3_EVIDENCE.txt` 第 28 行 + F 节；`HANDOVER.md` §23 | 载荷 `x\nlog -t P1UID \`id\`` → tx 10070 → `TRANSACT=true` → **`I P1UID : uid=0(root) gid=1010(wifi) … context=u:r:oplus_wifi_service:s0`**；第二次独立复现（`P1UID2`，F 节）再次回显 `uid=0(root)`。两次调用方均 uid 2000(shell) |
| ④ 负知识表正式推翻旧判断 | `HANDOVER.md` §6 负知识表第 434 行 | "'注入均被 INVAILD_PARAMETER 拒绝 ⇒ 该面不可利用' —— **推翻（§23，上机）**" |

**更正后的准确结论**：

- shell（uid 2000）经真客户端可达 `wifi` binder tx 10069/10070，门槛是公开接口描述符（§11 动态已证）；
- 部分常见 shell 元字符（`;`/`|`/`$()`）被 regex 拒绝，但 **`\n`/反引号可绕过 11 字符黑名单**，已两次触发**受限 UID 0 命令执行**——执行者 `uid=0(root)`、组含 `net_admin`、域 `u:r:oplus_wifi_service:s0`（§23 + P1 原始日志）；
- 这是"**受限 UID 0 命令执行**"而非"可用 ROOT"：该域读不到 `/data/system`、`selinuxfs`、`proc_security`、`shell_data_file`（§23.3），仍缺域逃逸；四层判定不变；

## 6. 候选 A 离线审计：`ioctl 0x89f1 → hdd_driver_command`（v12.3.1 新增）

> 纯离线反汇编 `0x38320`（函数长 229 条指令），产物 `artifacts_adb/r1_wlan_reach/hdd_driver_command.{full,calls}.txt`。**无上机、无动态输入。**

### 6.1 入口与调用关系

- `hdd_ioctl@0x38050` 在 `0x38138` 判 `w21==0x89fd`、否则落到 `0x381fc` 判 `w21==0x89f1` → `__wlan_hdd_validate_context` → `bl 0x38320`。即 `0x89f1` 的消费者是 `hdd_driver_command`，与 `0x89fd`（FTM）是**并列的两个命令号**。
- `hdd_driver_command` 以 `x0=adapter`、`x1=ioctl arg` 进入，命令串与长度来自 `[x22+0xc]`（ioctl 结构长度字段），经内核态复制后解析。**不是**直接来自 Binder/HIDL 的字符串。

### 6.2 输入链与安全不变量（逐指令）

| 环节 | 指令 / 证据 | 不变量 |
|---|---|---|
| 长度上界 | `0x383f4 ldrsw x5,[x22,#0xc]` → `sub w8,w5,#1` → `cmp w8,#2,lsl#12`（=0x2000）→ `b.lo 0x38430`，否则 `w23=-0x16` 退出 | **长度 ≤ 0x2000（8192）**，超限拒绝 |
| 分配 | `0x38430 add x0,x5,#1` → `__qdf_mem_malloc`（分配 length+1） | 为 NUL 预留 1 字节 |
| 复制 | `__check_object_size` → `__arch_copy_from_user(x20, x24, x23)`（`0x3848c`） | 目标为堆缓冲、长度受上界约束 |
| **NUL 终止** | `0x384ec strb wzr,[x20,x8]`（`x8=[x22+0xc]`） | **显式在 length 处写 0**，保证后续字符串函数不越界 |
| 命令切分 | `0x38510 strchrnul(x20, #0x20)`（分隔符=空格）→ `w23 = 命令名长度` | 命令名与参数分离 |
| 命令表匹配 | 表基 `[x21+0x10]`、`x28=0x10+i*0x18`（项 0x18 B）、`cmp x27,#0x62`（**98 项**）、逐项 `strlen` 比长 + `strncasecmp`（`0x38574`，大小写不敏感） | **白名单**：仅已注册命令名可执行 |
| 分发 | `0x385a4 ldr x8,[x28,#-8]` → `blr x8`（间接 handler），传 `(adapter, ctx, cmd, len, arg)` | handler 为函数指针表（运行时结构，静态未逐项绑定） |
| 未匹配 | `0x385ec qdf_mtrace` + `qdf_trace_msg` → `w23=-0x20c`（-524=ENOTSUPP） | 未知命令统一拒绝 |
| 错误清理 | 所有退出路径 `__qdf_mem_free(x20)`（`0x38648`） | 无泄露路径 |

**判定**：候选 A 是一个**有界、NUL 终止、白名单分发、全路径释放**的命令解释器。这些不变量使"用户态长度字段直接越界"的朴素假设不成立；若要证伪，须逐 handler 审参数语义（属 R3 深审），而非停在长度维度。

### 6.3 与 Binder / iwpriv 的关系（诚实边界）

- 复审建议"检查 Binder 命令执行链与 `/odm/bin/iwpriv` 的关系，确认 `hdd_driver_command` 与 FTM testmode 是否有可到达的调用关系"。本轮结论：
  - **用户态链**：`executeDriverCommand` → `/odm/bin/iwpriv <input>` → `/vendor/bin/sh -c`（`WIFI_P1_ROOT_COMMAND_AUDIT.md` §2，uid 0）；
  - **内核态链**：`hdd_ioctl 0x89f1` → `hdd_driver_command`（本文 §6.1–6.2）；
  - 两者都作用于 wlan0，但**现有物料无法静态证明 iwpriv 的某个子命令最终走到 `0x89f1`**——缺 `/odm/bin/iwpriv` 二进制（SELinux 拒读，见 `F16_WIFI_FTM_TRACE.md` §6）与其 ioctl 号的绑定。
