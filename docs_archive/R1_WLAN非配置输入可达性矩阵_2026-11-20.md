## 0. 结论先行

1. **R1 交付：一张非配置输入可达性矩阵（§2）+ 候选排序（§3）+ 明确未覆盖范围（§4）。本阶段不下漏洞结论。**
2. **三个输入面类别在模块二进制中被证实存在且"输入可控"**：① net_device ioctl（`hdd_ioctl`，两个命令号）；② cfg80211 testmode / FTM（`wlan_ioctl_ftm_testmode_cmd`）；③ cfg80211 vendor/管理帧注册面（大量 `wlan_hdd_cfg80211_*`）。它们均有用户态可控字节 + 明确的拷贝链。
3. **但可达域是决定性约束**：驱动侧 ioctl / cfg80211 面要求持有 wlan0 设备或 `CAP_NET_ADMIN` + nl80211 socket——**仅 `oplus_wifi_service`（uid 0，net_admin 组，CapEff `0x13000` 含 NET_ADMIN）满足；shell 域（uid 2000）不满足**。唯一从 shell 可达的 WLAN 输入通道是 Binder 私有事务（tx 10070），而它**已由 `F16_WIFI_FTM_TRACE.md` §12 审计到终局**：到 root 服务的参数白名单命令，注入被 `-3 INVAILD_PARAMETER` 拒绝，不产生 uid 0。
4. **候选排序结论：R3 的唯一合格候选是"ioctl `0x89f1` → `hdd_driver_command`"面**（固定 16/12 B 输入、消费者明确、有可检验不变量）；"FTM testmode"面作为次级候选（有 `≤0x800` 长度门 + `__check_object_size` 不变量）。**两者都属于驱动面，即便达成也不给 uid 0**（与现有 Wi-Fi 私有事务"到 root 服务命令接口"同类），且**验证它们需要能操作 wlan0 的域 + 上机，超出当前授权**。按 R1 停止条件，本轮停在授权门前，不进入 R3。

### 2.1 关于 shell 可达的"Binder 私有事务"通道（非 .ko 面，但必须并入判断）

`artifacts_adb/binder_audit/F16_WIFI_FTM_TRACE.md` 已把这条链审计到终局：

- shell（uid 2000）经真客户端可达 `wifi` binder tx 10069/10070，唯一门槛是公开接口描述符 `android.net.wifi.IOplusWifiManager`（§11，动态已证）；
- 下游是 root HIDL 服务 `vendor.oplus.hardware.wifi@1.1-service`（`user root`，caps `NET_ADMIN NET_RAW SYS_MODULE`），`executeDriverCommand(String)` 的入参逐字回显（§7/§12）；
- **但所有携带 shell 元字符的注入串均被 `-3 INVAILD_PARAMETER` 拒绝，"入参直通 sh -c"已撤回**（§12），无任何一次回显 `uid=0(root)`；
- ⇒ 这是"到 root 服务参数白名单命令"的通道，**不产生 uid 0，也未经由 qcacld 驱动 ioctl 的已证路径**。它与本文 §2 的驱动面 A/B 是两条不同的链，不可混同。

## 3. 候选排序（进入 R3 的门槛评估）

按 v13 R1 停止条件：只有同时满足"真实入口可达 + 输入可控 + 存在可检验安全不变量"的候选才进入 R3。

| 排序 | 候选 | 入口可达 | 输入可控 | 可检验不变量 | 是否满足 R3 门槛 |
|---|---|---|---|---|---|
| 1 | A：`0x89f1` → `hdd_driver_command` | 模块内确认；**域可达需 wifi uid0（上机）** | 是（固定 16/12 B） | 是（固定长度 + `PF_KTHREAD` 门，可逐指令核对消费者） | **待授权门前**：门槛①②成立（②在 wifi 域），③需 R3 审 `hdd_driver_command` 长度处理；非 uid0 收益 |
| 2 | B：FTM testmode `0x89fd` | 同上 | 是（≤0x800） | **是**（`cmp w21,#0x800` + `__check_object_size` + 分配/拷贝/传递长度同源 w21） | 次级；不变量已初步成立，R3 收益低 |
| 3 | C：cfg80211 vendor 面 | wifi uid0 域可达 | 是（未量化） | 未建立 | 面太广、域受限、无具体假设 ⇒ 不进入 R3 |
| 4 | E：debugfs 写面 | 未取证 | 未取证 | 未建立 | 遗留，先只读核验权限 |

**排序说明**：候选 A/B 都止于"驱动面"——即便找到可证伪缺陷，收益是"在 wifi uid0 域内的驱动状态影响"，**不是 uid 0 提权**（当前 Wi-Fi 私有事务已提供该域的 UID 0 命令执行）。项目 v12.2 主线已收口，不为"非 uid0 收益"重开 R3；且验证需上机 + 可操作 wlan0，超出当前授权。

## 4. 明确未覆盖范围（负结果的范围声明）

1. **未取证的设备侧事实**：wlan0 节点权限/SELinux 标签、debugfs 是否挂载可写、日志字符设备节点名与权限——这些需只读上机，本文未授权也不推测。
2. **未逐项量化的输入面**：~300 个 `wlan_hdd_cfg80211_*` 的 NL 属性长度/索引仅枚举符号，未逐一反汇编（R1 不要求深审；无具体假设即不进入 R3）。
3. **字符串引用限制**：`ko_fn.py` 未解析 `MOVW_UABS_G*` 重定位（§55.4），设备名/格式串只能从原始字节粗查，未做符号级精确绑定。
4. **2.1 的下游**：`IOppoWifiService` 的 vendor HAL 实现已在 `F16_WIFI_FTM_TRACE.md` §7 解出并审计，本文直接引用其终局结论，不重复。
5. **范围表述**：本文结论限定为"在 `qca_cld3_wlan.ko`（SHA `f45c1c1c…`）及既有取证集合内，非配置输入面的可达性分诊"；换 SPL/构建或换物料哈希即作废。
