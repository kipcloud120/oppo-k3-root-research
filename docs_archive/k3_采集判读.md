# K3 实机 ADB 采集判读（2026-11-13）

- 数据源：`k3_info.txt`（原始输出）、`k3_kernel_config.txt`（`/proc/config.gz` 解压）
- 设备：`<redacted>` / PCGM00 / OP4679 / sdm710；ADB 1.0.41 (36.0.1)；`uid=2000(shell)`
- 采集方式：全部只读。`adb shell` 输出在**主机端重定向落盘**，未向设备写入任何文件（比清单 §2 的 `/sdcard/k3_info.txt` 中转更严格，符合 §5 只读约束）。未执行任何 reboot / fastboot / flash / 改动 settings / 卸载操作。

## 1. 首要结论：清单所依据的镜像假设不成立

| 项 | 清单预期（C.17 镜像） | 实机实测 | 判定 |
|---|---|---|---|
| A2 `ro.build.display.id` | `PCGM00_11_C.17` | `PCGM00_11_F.16` | **不一致** |
| A3 `security_patch` | `2021-05-05` | `2022-04-05` | **不一致** |
| A4 Android 版本 | `10` | `11`（SDK 30） | **不一致** |
| A11 内核版本 | `4.9.186` | `4.9.227-perf+`（`#1 SMP PREEMPT Wed Mar 26 16:32:43 CST 2025`，clang 10.0.7） | **不一致** |
| `fingerprint` | — | `OPPO/PCGM00/OP4679:11/RKQ1.201217.002/1704167642389:user/release-keys` | 与 bootimage/vendor 三处一致 |
| 完整版本号 | — | `PCGM00_11_F.16_2025032621191106` / OTA `PCGM00_11.F.16_3160_202503262119` | 2025-03-26 构建 |

**按清单 §4 判读规则：A2/A3/A11 与镜像不一致 → 我们分析的不是这台机器，基于 C.17 镜像的静态分析结论（结构体偏移、符号地址、可利用性评估）对本机作废，需重新取 F.16 固件重做。**

这不是采集误差：`/proc/config.gz` 头部为 `Linux/arm64 4.9.227 Kernel Configuration`，与运行时 `uname -a` 完全一致，且 `ro.build.kernel.id=4.9.227`、`ro.bootimage.build.fingerprint` 与 `ro.build.fingerprint` 一致，构成"运行内核 = 当前系统镜像"的完整证据链。合理推断是设备已 OTA 到 F.16，而工作区内的 C.17 是历史版本。

**A5 未触发 orange 分支**：`verifiedbootstate=green`、`flash.locked=1`、`vbmeta.device_state=locked`、`realme.lockstate=1`，BL 仍锁定 → 清单 §4 的"直接走 Magisk"捷径不成立，临时 root / 解锁路线的前提仍然成立，只是**目标版本需要重定**。

## 3. 与清单 §0 权限推定的偏差

清单 §0 的权限表有两处需要修正：

| 项 | 清单 §0 推定 | 实测 | 影响 |
|---|---|---|---|
| `/proc/cmdline` | ✅ 能读 | ❌ `Permission denied` | **A12 无法回答**，KASLR 相关启动参数与 `skip_initramfs` 均不可判定；`/proc/bootconfig` 不存在，无替代来源 |
| `/proc/kallsyms` | ❌ 全 0 | ❌ 直接 `Permission denied` | 结论方向一致且更强：提权前拿不到任何符号信息，KASLR 必须运行时泄露 |
| `kptr_restrict` | 可读（预期 1/2） | ❌ `Permission denied` | 无法通过 sysctl 判定；但拒绝本身等价于"无松口" |
| `/proc/slabinfo` | ❌ 大概率拒绝 | ✅ **完全可读** | **重要松口**：SLUB 布局可运行时精调，推翻清单 §0「SLUB 布局无法据此精调」的判断 |
| `dmesg` | ❌ 拒绝 | ❌ `klogctl: Permission denied` | 与预期一致 |
| `/proc/config.gz` | 仅要求 `ls -l` | ✅ 可读且已拉取（33655 B gzip → 5622 行配置） | **额外收获**：内核攻击面配置可直接静态确认 |

其余与预期一致：`getenforce=Enforcing`、`id=uid=2000(shell) context=u:r:shell:s0`、`/dev/block/dm-0 /` 与 `dm-1 /vendor` 走 dm-verity、`ro.build.type=user`。

清单 §2 的 grep 为 `deep|deeptest|coloros.deeptesting`，实机命中 `package:com.coloros.deepthinker`。**该包不是深度测试 APP**。已补做精确核查：

- `pm path com.coloros.deeptesting` → 无输出
- `pm list packages | grep -i deeptest` → `(none)`

故 **B5 = N，深度测试 APP 未安装**，官方解锁路径不能"直接试"。（`k3_info.txt` 第 170 行因 `pm path` 无输出而与下一行前缀连写，属排版现象，不影响证据。）

## 6. 内核配置要点（来自实机 `/proc/config.gz`，非镜像静态提取）

对利用可行性有直接影响的配置：

| 配置 | 值 | 含义 |
|---|---|---|
| `CONFIG_RELOCATABLE` / `CONFIG_RANDOMIZE_BASE` | `y` / `y` | KASLR 开启，运行时基址必须泄露 |
| `CONFIG_ARM64_PAN` / `CONFIG_ARM64_UAO` | `y` / `y` | PAN 生效，内核直接读用户态内存受限制 |
| `CONFIG_ARM64_VA_BITS` | `39` | 内核虚拟地址布局 |
| `CONFIG_SLAB_FREELIST_RANDOM` | **not set** | freelist 未随机化，对 SLUB 堆布局利用有利 |
| `CONFIG_SLUB_DEBUG` / `CONFIG_SLUB` | `y` / `y` | 配合可读的 `/proc/slabinfo`，堆喷可观测 |
| `CONFIG_BPF_SYSCALL` / `CONFIG_BPF_JIT` | `y` / **not set** | eBPF 系统调用可用但无 JIT |
| `CONFIG_USER_NS` | **not set** | 无 user namespace 提权路径 |
| `CONFIG_KPROBES` / `UPROBES` / `DEVMEM` / `PROC_KCORE` / `KASAN` / `UBSAN` | not set | 调试与内核内存接口关闭 |
| `CONFIG_FTRACE` / `CONFIG_PREEMPT` / `CONFIG_HZ` | `y` / `y` / `100` | 抢占式内核 |
| `CONFIG_HARDENED_USERCOPY` / `CONFIG_DEBUG_RODATA` / `CONFIG_SECCOMP_FILTER` | `y` | 常规加固在位 |
| `CONFIG_SECURITY_SELINUX_DEVELOP` | `y` | 编译期允许 permissive，但运行时为 `Enforcing` |
| `CONFIG_SECURITY_DMESG_RESTRICT` | **not set** | `dmesg` 被拒来自 SELinux 策略，非内核配置 |

## 7. 对既有报告的影响与下一步建议

1. **停止把 C.17 镜像的结构体偏移/符号地址用于本机**。需重新获取与 `PCGM00_11_F.16`（fingerprint 尾号 `1704167642389`，2025-03-26 构建）对应的 `boot.img` / `vendor.img` / 内核，重做静态提取。
2. **CVE 适配范围需重算**：补丁级别由 2021-05-05 推进到 2022-04-05，且 Android 10 → 11、内核 4.9.186 → 4.9.227，2021 年前的大部分公开 CVE 大概率已修复。应对 `K3_CVE解锁可行性分析.md` 的候选 CVE 逐条重新核对补丁窗口。
3. **新增可用素材**：`/proc/config.gz` 全文与 `/proc/slabinfo` 全量快照已落盘，可直接用于利用可行性评估，无需再连机。
4. **仍不可得**：内核符号地址、`/proc/cmdline`、dmesg、`kptr_restrict`、任何分区裸读（需 root）。清单 §0 的核心判断「拿不到利用素材、KASLR 必须运行时泄露」依然成立。
5. **BL 状态未变**（green/locked），A5=orange 的捷径不成立，OEM 解锁开关未触碰。
