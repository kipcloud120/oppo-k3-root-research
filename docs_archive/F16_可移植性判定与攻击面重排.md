# F.16（4.9.227）临时 ROOT：可移植性判定 & 攻击面重排

- 日期：2026-11-13
- 基线：`firmware_F16/`（boot.img 解出 `kernel.decompressed`，banner `4.9.227-perf+`，2025-03-26，SHA256 `95a70412…`），与 ADB 实机逐项一致
- 符号证据：本次从 F.16 内核恢复 **123784 个符号**，identifier-like **100.0%**（`firmware_F16/kallsyms_out.txt`）
- 方法：压缩 kallsyms 恢复（`tools/f16_syms.py` + 直接推导 token_index）+ 精确符号检索 + 对照 `k3_kernel_config.txt` 与 ADB 运行时面

---

## 0. 结论先行

1. **GhostLock（CVE-2026-43499）在 F.16 / 4.9.227 上「机制成立」**：futex PI + rt_mutex 全链路函数**一个不缺**，且 `remove_waiter` 以**独立符号**存在（`@0x000ae9c8`）；4.9.227 的补丁级别（2022-04-05）远早于 2026 修复 → **必然 pre-fix**；且不依赖 `CONFIG_USER_NS`（本机 `USER_NS=n`）。→ 但**仍需针对 4.9.227 做利用开发**，非移植现成 PoC。
2. **攻击面重排（按"确定性×可达性"）**：**① GhostLock/futex（唯一"已知未修复"）→ ② KGSL(kgsl-3d0) → ③ ION → ④ Binder → ⑤ ashmem（被 SELinux 挡）/ tracefs（半可用）**。
3. **KGSL 是"面最大"但"补丁未证"**：驱动 1239 符号、57 个 ioctl handler、`/dev/kgsl-3d0` 世界可打开；但具体哪个 CVE 在 4.9.227 仍未修，需要逐个核对（vendor 驱动不随 SPL 走）。
4. C.17 的全部偏移/符号**不可复用**（4.9.186→4.9.227，函数相对位置整体位移）。

## 2. GhostLock 可移植性判定

| 判据 | 结论 | 依据 |
|---|---|---|
| 缺陷代码是否存在 | **是** | 全链路函数齐全；`remove_waiter` 独立符号 |
| 是否已修复 | **否（pre-fix）** | 4.9.227 / SPL 2022-04-05，远早于 2026 修复 commit |
| 是否依赖 USER_NS | **否** | futex 本地竞态；`CONFIG_USER_NS=n` 不影响 |
| 现成 PoC 可直用 | **否** | 公开 GhostLock 针对 GKI 6.6/6.12；4.9 非 GKI 结构/偏移不同 |
| 与 C.17 偏移可比 | **否** | 例如 `remove_waiter`：C.17 `0x0aa3a4` → F.16 `0x0ae9c8`，整体位移≠0 |
| 可达性（无需设备节点） | **是** | futex 是系统调用；shell 域可 `adb push` 原生程序到 `/data/local/tmp` 执行，不需要 `/dev` 节点权限 |

**判定**：**机制可行、需 4.9.227 专属利用开发**（结构体偏移重提 + 竞态复现 + UAF→读写 + 提权 + KASLR 泄露/暴力）。工作量量级与此前评估一致（15–25 人日），但**这次是"确定有洞"**，而非"猜测"。

## 3. 攻击面重排（临时 root，从 shell 视角）

排序准则：**① 补丁确定性（是否已知未修复）② 可达性（shell 能否触发）③ 面规模/CVE 密度**。

| 排名 | 面 | 补丁确定性 | 可达性 | 面规模 | 综合 |
|---|---|---|---|---|---|
| **1** | **GhostLock / futex** | **高（必然未修）** | 高（syscall，无需节点） | 中（单点竞态） | **首选：确定性最高** |
| **2** | **KGSL / kgsl-3d0** | 低（需逐个核 vendor CVE） | **最高（世界可 open，57 ioctl）** | **最大（1239 符号）** | 次选：面最大，需 CVE 排查 |
| 3 | ION | 低-中 | 高（open OK） | 中（237 符号） | 备选 |
| 4 | Binder | 中（2019 前多已修） | 高（世界 rw） | 大 | 备选 |
| 5 | ashmem | 中 | **低（SELinux 拒绝 shell open）** | 中 | 降级 |
| 6 | tracefs | 低 | 低（仅 trace 可读） | 小 | 情报面 |

**关键判断**：
- 在 SPL 2022-04-05 下，**AOSP 内核核心的 ≤2022-04 CVE 基本已修**；唯一"确定未修"的核心链就是 **GhostLock（2026）**。这使 futex/GhostLock 从"备选"升为**确定性首选**。
- **KGSL/ION 属 vendor 驱动，不随 SPL 走**：其补丁由高通/OEM 单独跟进，历史上长期滞后。因此 kgsl 虽"面最大"，但**必须先确认某个具体 CVE 在 4.9.227 仍未修**，才能升级为首选。

## 5. 下一步（决策点）

1. **主线（推荐）**：以 **GhostLock on 4.9.227** 立项做利用开发。第一步是**结构体偏移提取 + 竞态触发复现**（`rt_mutex_waiter`/`futex_q`/`rt_mutex` 字段、`remove_waiter` 调用点）；能稳定触发 UAF 再谈读写原语。
2. **并行（CVE 排查）**：对 **KGSL** 逐个核对 4.9.227 上未修的 Adreno/msm 驱动 CVE（vendor 公告 + 代码比对），若有"免 userns、shell 可达"的，可并行推进（面更大、可能更易）。
3. **仍应优先试**：官方深度测试解锁（受理则直接持久 root，终止本线）。
