# OPPO K3 项目评审与下一步工作规划（v13）

> 评审日期：2026-11-20  
> 对应项目版本：v12.2（`HANDOVER.md` §63）  
> 评审性质：交接材料与证据链的文档评审、研究优先级重排；**未连接设备、未重新反汇编、未独立复跑全部实验**。本文不替代原始证据，技术事实以根目录 `HANDOVER.md` 为权威。

## 0. 结论先行

1. **维持现有四层判定：Wi-Fi 域内 UID 0 命令执行已达成；可用 ROOT、持久 ROOT 均为 NO-GO。** 当前没有证据支持把“受限 UID 0”写成“完整 ROOT”，也没有持久化成果。
2. **KGSL 生命周期主线可以阶段性关闭，不建议在本机继续重复投入。** K1/K2 已在声明范围内形成静态不变量和最小上机证据；sparse 子树不可达，K3 并发实验与“不重启”约束冲突。继续扫同一批入口的边际收益很低。
3. **GhostLock 应继续冻结。** ① 类 mm 线性映射地址已恢复，不等于可控 `rt_mutex` 地址、W 线程栈地址或 `.text` KASLR slide；②/③ 没有新信息源时，不应重复 M1/M2 或已审栈接口。
4. **下一条主线应从“继续找漏洞”切换为“先建立真实输入可达性，再做定向审计”。** 优先处理已有 `qca_cld3_wlan.ko` 的非配置输入面，并对其余 vendor 模块做只读、分阶段的可达性筛选；没有可控输入路径的模块不进入深度审计。
5. **下一轮首先应完成交接卫生修正。** 若干入口文档仍把已关闭的 KGSL 非 sparse 对称缺陷列为“当前可动方向”，`docs_archive/README.md` 也未登记 v012。若不修正，后续 AI 容易按过期优先级重做工作。
6. **任何新上机动作均需重新取得明确授权。** 继承现有硬约束：不重启、不写 `persist`、不改分区/配置、不重载 WLAN、不提交 GPU 命令、不 mmap、不构造悬空映射、不做 GhostLock 端到端 PoC。

**推荐决策：接受 v12.2 的阶段性收口；下一轮以“文档同步 + 可达性矩阵 + 最多一个新靶面的定向审计”为限，不以再次证明 NO-GO 为目标。**

## 1. 当前成果与判定复核

| 层次 / 方向 | 评审认可的状态 | 证据范围与不可外推项 |
|---|---|---|
| Wi-Fi 私有事务 → UID 0 命令执行 | **正向成果，已达成** | 受 `u:r:oplus_wifi_service:s0`、能力集及 SELinux 限制；不是脱离域的系统管理能力 |
| 可用 ROOT | **NO-GO** | 域逃逸、内核原语及地址前提均未形成可用链；该判定限本机、本固件、不解 BL |
| 持久 ROOT | **NO-GO** | 未做持久化写入，也不应把“不写持久化”与“技术上已可实现但未执行”混为一谈 |
| GhostLock | **冻结** | ① 类地址闭合仅本次开机有效；② 可控 `rt_mutex` 地址未闭合，③ 在已审接口范围内无可用 oracle，`.text` slide 未获得 |
| KGSL 长度维度 | **闭合于本轮枚举范围** | 54 入口、14 拷贝点的长度判界已完成；不表示 KGSL 全部代码无缺陷 |
| KGSL sparse / KO-1 | **本机不可达，代码层 latent** | 六个 sparse 入口均在分配前返回 `ENOTSUPP(524)`；不能写成“上游代码没有缺陷” |
| KGSL 非 sparse K2 | **在声明的可达面内阶段性达成** | I10–I12 为静态证据；I4 上机覆盖立即 free 后 id 撤销；延迟释放和并发不能由该实验外推 |
| KGSL K3 | **未做，登记不作** | 这是明确的覆盖缺口，不是“并发已证明安全”，也不是“已发现并发漏洞” |
| WLAN 配置解析器 C1 | **当前配置下无可达输入路径，降级/冻结** | `persist` 可写副本不进入当前 `request_firmware` 消费链；`sscanf` 未审不能单独构成重开理由 |
| 其余 vendor `.ko` | **主要未覆盖面** | 已有 41 项目录记录和 37 行 `modules.load` 清单，但只有 `qca_cld3_wlan.ko` 已取得并做深入分析；不能据此推断其余模块可达或存在缺陷 |

### 1.1 对 K2 口径的具体限制

v12.2 的阶段性关闭是合理的，但后续引用必须保留以下限定：

- `GPUOBJ_ALLOC → GPUOBJ_FREE → 再次 FREE` 的实测直接支持的是**立即释放路径的 id 撤销与重复 free 拒绝**。
- `param` 阶段使用不存在 id / 非法参数，主要证明分支解析和错误门符合预期；它不等价于真实对象在 timestamp/fence 回调中的完整生命周期验证。
- I12 对延迟释放的支持主要来自静态路径配对；K3 的 fence signal 与 free 竞态仍未动态验证。
- 因此推荐统一表述为：**“K2 在本机非 sparse、已审静态路径及立即释放判定实验范围内达成；延迟释放动态行为与 K3 不在本次实证范围内。”**

这不会推翻主线收口，只是防止后来者把局部证据扩大成全称安全证明。

## 2. 项目质量评审

### 2.1 值得保留的做法

1. **结论分层清楚。** 受限 UID 0、可用 ROOT、持久 ROOT、地址泄露和 KGSL 生命周期分别记账，避免单点突破被包装成最终目标达成。
2. **判据可证伪。** KO-1 事先列出推翻条件，随后由上机结果命中“sparse 不支持”而关闭；这是有效的研究闭环。
3. **静态与动态证据分离。** 多数结论能区分“二进制形态成立”“入口可达”“动态已验证”“可利用”，后续应继续沿用。
4. **工具错误被纳入负知识。** 哈希/桶统计量、搜索窗口、`errno` 读取和 `min` 长度语义均有自我更正记录。此类记录比只保留成功结论更有交接价值。
5. **设备边界与终态记录完整。** `boot_id`、`uptime`、临时探针清理、内核日志和禁止写入项形成了可审计的操作链。

### 2.2 主要方法风险

1. **枚举完备性仍是最大认识论风险。** “已审接口范围内无 oracle”不能外推为所有驱动、debugfs 或未来固件均无 oracle。
2. **长文档中的历史口径容易被误读。** `HANDOVER.md` 保留历史原文是优点，但根目录多个摘要和审阅清单若不同步，会使旧优先级看起来仍然有效。
3. **静态不变量不自动等于动态安全。** 后续文档必须明确区分“静态未发现问题”“判定型实验未证伪”“压力/竞态已验证”。
4. **NO-GO 是当前证据下的工程决策，不是数学不可能性。** 新模块、新可达域、新固件或新地址源都可能改变研究排序，但在出现具体证据前不应无限保留所有方向为高优先级。

## 4. 下一步工作规划

### R0 — 交接同步与可复现基线（P0，默认纯离线）

**目标：让后续工作在同一个事实基线上开始。**

工作内容：

1. 完成第 3 节 P0/P1 文档修正，并登记本评审。
2. 建立一张覆盖台账，至少包含：方向、精确范围、可达域、静态证据、动态证据、未覆盖项、停止条件、重开条件、权威章节。
3. 核对本地物料是否存在、路径是否一致；如执行离线复跑，记录工具版本、输入文件哈希、命令和退出码。不得把“脚本跑通”写成“安全结论再次得到真机验证”。
4. 若 `vmlinux.elf`、设备固件或 SPL 不一致，停止沿用偏移和旧结论，先重建基线。

**验收：** 新读者只从入口文档即可得到一致优先级；每个“关闭/冻结”均有范围和重开条件；离线复跑产物可追溯到具体输入。

### R1 — WLAN 非配置输入面的可达性地图（P1，优先使用现有物料）

**为什么优先：** `qca_cld3_wlan.ko` 已在本地且符号完整，不需要先取新二进制；C1 关闭的只是配置解析输入，不代表整个 WLAN 模块没有其它输入面。

**先做离线，后决定是否申请只读上机：**

1. 从模块入口和既有调用记录建立“输入源 → 分派入口 → 权限/域 → 状态改变 → 消费者”表。输入类别可覆盖 ioctl、netlink/cfg80211/vendor 命令、sysfs 参数及已有服务间接调用，但必须逐项给出证据，不因符号存在就判定可达。
2. 排除当前只读固件配置链，不重做 `cfg_parse`，不审 `sscanf` 作为独立主线。
3. 对每个候选入口回答四个问题：哪个上下文可触发；哪些字节/序号/生命周期由该上下文控制；调用是否改变驱动状态；最终到达哪个解析或状态机函数。
4. 只有同时满足“真实入口可达 + 输入可控 + 存在可检验的安全不变量”的候选，才进入 R3。

**停止条件：** 所有候选均止步于权限门、无攻击者输入或无可审计消费者，则关闭本子方向，不以“模块很大”作为继续投入理由。  
**交付：** 一张可达性矩阵、候选排序、每项证据位置、明确未覆盖范围；此阶段不需要漏洞结论。

### R2 — 其余 vendor 模块的只读分诊（P1，先可达性，后取物料）

**现状边界：** `modules.load` 有 37 个模块条目；§55 的“41 项”包含目录内索引等文件。二者不是同一计数口径。多数模块属于音频依赖图，另有 `llcc_perfmon`、`mpq-*`、`rdbg` 等；**名称不构成可达性或风险证据。**

执行顺序：

1. 先利用现有 `modules.load` / `modules.dep` 建立依赖图和物料清单。
2. 如获只读上机授权，再核对实际加载状态、暴露的设备/接口、权限与 SELinux 上下文，以及 shell / 现有 UID 0 域是否可触发。只记录事实，不加载、卸载或修改模块。
3. 按四项排序：当前可达性、输入可控性、物料取得成本、在“不重启”约束下的可验证性。优先级采用高/中/低及理由，不做无依据的数值评分。
4. **不要一次性拉取并深审全部模块。** 每轮最多选择一个最高优先级靶面；只有入选后才只读取得对应 `.ko`。

**停止条件：** 未加载且无合法触发路径、接口不可达、输入不可控的模块直接降级；深审数量不是项目目标。  
**交付：** 模块—接口—域—输入—物料五列表，以及一个进入 R3 的候选或“本轮无合格候选”的负结果。

### R3 — 单一入选靶面的定向离线审计（P2，必须通过 R1/R2 门槛）

对每个入选靶面按以下顺序推进：

1. 写一个具体、可证伪的假设，禁止以“历史 CVE 多”“模块复杂”为立项理由。
2. 先确定用户输入长度、索引、类型和权限门，再审对象所有权、释放前提、错误路径和并发状态。
3. 每个结论落到函数、指令/重定位或实测记录；源码只作语义参照，本机二进制才是形态证据。
4. 若发现候选缺陷，先写推翻条件和最小判定实验，不直接写“漏洞已确认”或“可利用”。
5. 任何会产生异常状态、悬空映射、模块重载或可能 panic 的动态验证，均不在当前设备授权默认范围内；应先停止并提交新的风险评审。

**验收：** 完成一个明确命题的证实/证伪及范围说明，而不是再增加一批未判定的“可疑点”。

| SELinux 域逃逸旧路径重算 | 冻结 | 新策略、capabilities、域转换或写后执行关系的具体反例 |

## 6. 安全与证据纪律（后续 AI 必须继承）

1. **默认纯离线。** 本文不授予任何新的设备操作权限；只读上机也应单独取得授权。
2. **不重启设备。** 任何可能导致 panic、GPU fault、WLAN 断链或系统不可恢复的动作均不得作为“快速验证”。
3. **不写持久位置。** 禁止写 `persist`、刷写/解锁、改分区、关闭或修改安全配置；不以“实验后恢复”为理由绕过。
4. **GPU 边界不变。** 不提交命令、不 mmap、不执行 IB、不构造悬空映射；已有判定型结果不得被用来授权更激进实验。
5. **上机记录完整。** 若另获授权，每阶段记录 `boot_id`、`uptime`、上下文、命令、原始返回、临时文件清理和异常日志；失败时先检查探针与 `errno`，再解释目标行为。
6. **负结果也必须有范围。** 使用“在本机/本构建/已审集合内未发现”，不要写“绝对不存在”。
7. **结论变更需要新证据。** 其它机型、其它 SPL、公开 CVE 或参考项目成功本身均不能推翻本机判定。

## 7. 建议的下一轮任务卡

后续 AI 可按以下顺序执行；若用户只要求继续研究而未授权上机，则仅完成离线部分并停止在授权门前。

### 任务 A：交接修正与覆盖台账

- 输入：本文第 3 节、根目录三份入口文档、`HANDOVER.md` §61–§63。
- 动作：只修正过期优先级、明确错误措辞和索引，不重写历史证据。
- 完成标准：不再有任何入口把 KGSL 非 sparse 对称审计或 GhostLock 旧路线列为当前主线。

### 任务 B：WLAN 非配置输入可达性矩阵

- 输入：本地 `vendor_ko/qca_cld3_wlan.ko`、`tools/ko_fn.py`、既有域与服务证据。
- 动作：离线枚举并逐项判断真实输入来源；不做配置解析器重复审计。
- 完成标准：产出一个满足 R3 门槛的候选，或给出带范围的无可达输入负结果。

### 任务 C：其余模块只读分诊

- 输入：`vendor_ko/modules.load`、`vendor_ko/modules.dep`；设备信息仅在另获授权后采集。
- 动作：依赖图、加载/接口/权限事实、优先级排序；不批量深审。
- 完成标准：最多推荐一个靶面进入 R3，并说明其它候选被降级的具体原因。

### 任务 D：单靶面定向审计
